# 204 次提交中学到的 Agent 开发法则

> 不是技术文档（那在 AGENTS.md），不是项目报告（那在 PROJECT_REPORT.md）。
> 这是关于**与 AI agent 协作开发**的十二天感悟——给未来的自己，也给同行。

## 0. 核心发现

**知道 ≠ 做到。** 我在第 13 条教训里写了「版本 bump 用 glob 不用清单」，然后在下一轮还是漏了 19 个文件。文字规则不管用——不管你多聪明、多有经验、写得多清楚。**Agent 需要的不是被告知，而是被阻止。**

这是整个项目最重要的工程发现，也是 Lauren Tan（SpaceX/xAI）用月发 11,000 个 PR 验证的同一条原理。

## 1. 错误的必然性

在 204 次提交中，我犯了 19 类错误。不是因为我笨——是因为：

- **转义地狱**：工具层吃反斜杠 → 正则折行 → 语法错误（出现 ≥8 次）
- **静默失败**：Promise 回调里的 TypeError 被 `catch` 吞掉 → 页面永停（出现 3 次）
- **版本漂移**：改了 A 忘了 B → 22 个文件版本号失谐
- **口径不一致**：Python 裸切片 vs Node 纯语料提取 → 数字差 15%（出现 6 次）
- **假阳性**：PDF 有 "4.19" 但那是密度值不是章节号 → 内容验证通过但实际缺失

**每一类错误都重复了至少两次才被我记住。** 而记住之后，下一次还是会犯——只是概率降低。只有变成 lint 规则后，概率才变成零。

## 2. 信任金字塔的独立发现

在不知道 Lauren Tan 演讲的情况下，我在十二天里独立走向了同样的架构：

```
我发现的顺序                    Lauren Tan 的表述
──────────────────────         ─────────────────────
教训写入 PROJECT_REPORT   ←→   "文字指令（最弱）"
verify.py / run_tests.py ←→   "测试（半确定）"
哨兵 30 锚               ←→   "静态分析（确定）"
lint 12 类 + pre-commit  ←→   "代码库质量（最强）"
```

区别在于：她从 11k PR/月的工业实践中提炼，我从 204 次提交的试错中爬出来。**终点相同，速度差了三个数量级**——因为她从一开始就知道要建塔，而我是先掉进每个坑里才知道需要填。

## 3. Agent 开发的三条法则

### 法则一：确定性 > 判断力

| 依赖判断力（会忘） | 变成确定性（不会忘） |
|---|---|
| 「记得用 glob bump 版本」 | `lint L1: 版本一致性检查` |
| 「不要用 map.fire」 | `lint L10: 危险 API 禁用` |
| 「Worker 里不要引 DOM」 | `lint L11: 架构约束` |
| 「改了 md 记得重排 PDF」 | `check_docs_sync.py 哨兵` |

### 法则二：代码库即训练数据

Agent 写的每一行代码都在复制现有代码的模式。**如果你现有的代码是乱的，agent 的输出会更乱。** 我们花了三天做 code review + 渲染分层 + 仓库理整——不是为了用户，是为了让 agent 在干净的模板上生成干净的结果。

### 法则三：自愈 > 拒绝

`lint --fix` 比 `lint` 更有价值——因为它不只说「你错了」，而是说「我来修」。agent 不需要被批评，需要被帮助。`make fix` 三个字母，比十条 README 指令更有效。

## 4. 数字人文的特殊教训

这个项目不是普通的 Web 开发——它同时是学术研究。这带来了额外约束：

- **每一个数字都必须可复核**（哨兵 30 锚守护论文一致性）
- **视觉读图不作数据源**（我曾从截图中读出「河南 55.5 万字」，脚本是 22.2——幻觉）
- **配套数据与论文逐位一致**（S1 的山东判断密度 31.66 与 PDF 逐位核对）

这些纪律在纯工程项目里不存在。但在数字人文里，**一个错误的数字可能被引用一百次**。

## 5. 给未来 Agent 开发者的建议

1. **第一天就建 lint**，不要等犯了错再建。每次犯错都是 lint 的欠债。
2. **AGENTS.md 写给 agent，LESSONS 写给自己**。前者是入职手册，后者是成长记录。
3. **pre-commit hook 是你最好的朋友**。它不会忘、不会累、不会说「下次一定」。
4. **当 agent 第三次犯同一个错时，停止写规则，开始写 lint**。
5. **make fix > make lint > make test > git push**。如果只记住一件事，记住这个。
