# 《水经注》数字人文平台 · 项目设计方案

> **项目代号**：水道经纬（Waterway Jingwei）——承方舆经纬命名
> **文本对象**：北魏·郦道元《水经注》四十卷，约 30 万字注文 + 7 千字经文
> **设计基础**：方舆经纬 v7.2.0 的全部基建（八件兵器 · 十六维度 · 二十五条教训）
> **日期**：2026-11-19

---

## 一、文本概况与核心差异

### 1.1 《水经注》是什么

```
《水经》（桑钦或郭璞，约 1.4 万字）
    ↓ 郦道元（470-527）作注
《水经注》（40 卷，约 30 万字注文）
    ├── 记载 1,252 条水道（经文原 137 条，注文扩充近十倍）
    ├── 沿岸记载：城邑、山岳、桥梁、津渡、湖泽、泉井、瀑布
    ├── 引书 400+ 种（其中大半已亡佚——引书考古学的宝库）
    └── 保存大量北魏时期的水文、生态、地质一手观察
```

### 1.2 与《读史方舆纪要》的结构差异

| 维度 | 方舆经纬（已完成） | 水道经纬（本设计） |
|---|---|---|
| **组织单元** | 府（面状行政区的中心点） | 水（线状地理实体） |
| **空间形态** | 离散点（1,489 个治所） | 连续折线（1,252 条水道轨迹） |
| **定位句式** | 「县名·府/州 方位 N 里」 | 「又东过 X 县南」序列 |
| **坐标类型** | (lat, lng) 单点 | [(lat₁,lng₁), …, (latₙ,lngₙ)] 折线 |
| **文本结构** | 单层（无经注之分） | 双层（经文+注文，需分离） |
| **空间粒度** | 府级（约 300km 尺度） | 县级+（约 30km 尺度——沿岸每个县） |
| **网络形态** | 府与府的共现（间接网络） | 水系分叉/合流（物理拓扑网络） |
| **时代** | 明末（17 世纪） | 北魏（6 世纪）——早 1,100 年 |

### 1.3 核心技术挑战

```
方舆经纬解过的问题          水道经纬的新问题
─────────────────────         ─────────────────────
点坐标三角化        →    河流折线重建（序列→路径）
名录解析（州县名）  →    经注分离（双层文本拆分）
府名共现网络        →    水系拓扑网络（干流-支流树）
单文本计量          →    双文本计量（经 137 条 vs 注 1,252 条）
明坐标库            →    北魏地名坐标库（大量古今异名）
```

## 二、数据管线设计

### 2.1 总体流程

```
获取文本（国学导航或 ctext.org）
    ↓
结构解析（卷 → 水系 → 经注分离 → 沿岸条目提取）
    ↓
水道轨迹重建（航点序列 → 坐标折线）
    ↓
沿岸地点坐标三角化（复用方舆经纬方法论）
    ↓
数据产物（river_data.js + site_data.js 共享坐标层）
    ↓
前端渲染 + 文本分析 + 论文产线
```

### 2.2 文本获取与经注分离

**获取来源**（按优先序）：

| 来源 | 格式 | 优劣 |
|---|---|---|
| 国学导航 | HTML 分卷页面 | 同方舆经纬——管线可复用 |
| ctext.org | 结构化 XML | 有段落标记但需 API 调用 |
| 已出版点校本 OCR | PDF | 质量最高但需 OCR |

**经注分离策略**：

```
方法 A（规则法，首选）：经文句式极度程式化
  经文模式：「X水出Y山/Z郡，东南流过A县B，……入C水/D海」
  特征：每句 < 15 字 · 无引书 · 无故事 · 地名密度极高

方法 B（对照法）：学界已有经文单独辑本（陈桥驿点校本标注）
  → 直接比照，在抓取文本中匹配经文片段

方法 C（统计法）：SLM 分类
  → 以已知经文为种子，训一个朴素贝叶斯/规则打分器
  → 按句打分：经文概率 = 高地名密度 × 低引书密度 × 低叙事密度
```

**实现**：方法 A 起步（正则 + 地名密度阈值），方法 B 校准，方法 C 兜底。

### 2.3 沿岸航点提取与河流折线重建

**核心句式库**（初步盘点）：

```
一、流向+过境（干流路径）：
  「又东过X县南」     → waypoint(县X, 方位=南, 顺序=n+1)
  「又东北过X郡西」   → waypoint(郡X, 方位=西, 顺序=n+1)
  「又南入X县境」     → waypoint(县X, 入境, 顺序=n+1)

二、支流汇入（拓扑边）：
  「X水出Y山，南流注之」   → tributary(X, joins=主流, at=当前段)
  「X水从西北来注之」      → tributary(X, direction=西北)
  「X水入焉」              → tributary(X, implicit)

三、终点：
  「入于海」「入于X水」「东入海」 → terminal(type=sea|river, target=X)
```

**河流折线算法**：

```
输入：waypoint 序列 [(地名₁, 方位₁), (地名₂, 方位₂), …, (地名ₙ, 方位ₙ)]
前提：每个地名已有坐标（复用方舆经纬坐标库 + 新增北魏地名）

Step 1  航点排序 = 文本出现顺序（郦道元按流向叙述）
Step 2  坐标连线 = 逐对连线（首版：直线段；进阶：Catmull-Rom 平滑）
Step 3  方位校正 = 「过X县南」→ 航点应在X县坐标之南偏移约 5km
Step 4  异常剔除 = 航点间距离 > 200km 时标记可疑（可能跳段或缺航点）
Step 5  拓扑验证 = 支流终点应接近主流某航点（距离 < 50km）

输出：GeoJSON LineString（每条水一道）+ FeatureCollection（全部水系）
```

### 2.4 坐标体系

**复用层**：方舆经纬的 380 处治所今地坐标（明府/州）可直接命中部分水经注地名（约 30% 的沿岸县在明代仍存在）。

**新增层**：北魏地名 → 今地坐标

| 方法 | 适用范围 | 精度 |
|---|---|---|
| 方舆经纬已有坐标直接匹配 | 同名县（约 400 个） | 高 |
| 郦学考据成果（陈桥驿等） | 学界已有今地对照表 | 高 |
| 水系拓扑约束推断 | 沿岸地点可由河流走向反推 | 中 |
| 行政沿革链（北魏→隋唐→明清） | 异名县追踪 | 中 |
| **人工标注兜底** | 剩余疑难地名 | 最终手段 |

**目标覆盖率**：主要水道（前 50 条）的航点 ≥ 80%；全部水道 ≥ 60%。

## 三、前端架构设计

### 3.1 页面结构

```
水道经纬/
  index.html          # 主页（河流地图 + 检索 + 分析）
  river.html          # 单水详情（轨迹 + 沿岸 + 原文 + 支流树）
  compare.html        # 古今对照（北魏水道 vs 现代水系）
  crossref.html       # 与方舆经纬互查（924 处引水经注）
```

### 3.2 地图可视化（核心新功能）

#### 河流轨迹渲染

```javascript
// Leaflet Polyline + 方向箭头 + 流量线宽
const river = L.polyline(waypoints, {
  color: "#2f5d70",
  weight: 4,           // 可按注文字数动态调宽
  opacity: 0.8
});

// 支流用渐变色（汇入点视觉收敛）
// 干流可切换为「跟随河流」模式：相机沿折线飞行
```

#### 新交互：「循水而读」

```
用户点击某条河流 → 高亮全轨迹 → 进入阅读模式
  → 屏幕分为两栏：左侧地图沿河移动，右侧显示对应段落的原文
  → 滚动文本 = 地图跟随移动（reading along the river）
  → 到达支流汇入点 → 可点击切换到支流阅读
  → 到达终点（入海/入河）→ 显示终点信息 + 相邻水道推荐
```

**这是水道经纬独有的体验**——方舆经纬是「点一个府看一个府」；水道经纬是「沿着一条河从源头走到入海」。

#### 新交互：「水系树」

```
侧栏显示当前水道在水系网络中的位置：
  淮水
    ├── 汝水
    │   ├── 澧水
    │   └── 潕水
    ├── 颍水
    │   ├── 洧水
    │   └── 濦水
    └── 泗水
        ├── 沂水
        └── 沭水
点击任一节点 → 地图飞至该水 + 打开详情
```

#### 古今对照

```
底图切换：北魏推想水道（我方折线）⇄ 现代自然水系（OSM/Natural Earth）
叠层模式：双线并显（古=虚线朱红 / 今=实线青蓝）
改道检测：两条线偏差 > 阈值的段落高亮为「改道区」
  → 最著名的案例：黄河夺淮（卷五·河水东注）vs 现代黄河走山东
```

## 四、文本分析层设计

### 4.1 基础计量（复用方舆经纬管线，换词表）

| 分析 | 方舆经纬 | 水道经纬 |
|---|---|---|
| 卷帙分布 | 15 省字数 | 40 卷字数（河水 5 卷独大） |
| 地名频次 | 192 府被引 | 1,252 水被提及 |
| 语汇密度 | 16 军事词 | **16 水文词**（源·流·注·决·溢·涸·涨·泝·渡·津·堰·堤·渠·灌·涨·涸） |
| 动词密度 | 14 攻守动词 | **14 水运动词**（出·过·迳·历·经·至·入·注·合·会·流·注·决·溢） |
| 引书分析 | 20 种高频引书 | **400+ 种引书**（大半已亡佚——最大亮点） |

### 4.2 独有分析层

#### （1）水道注意力分布

```
问题：郦道元对 1,252 条水的注意力如何分配？
指标：每条水的注文字数 / 航点数 / 引书数 / 传说数
预期：河水（黄河）独占 5 卷 ≈ 1/8 全书——长尾分布极重
发现：北南方不对称（郦道元为北魏人，南方水记述依赖文献而非亲历）
```

#### （2）引书考古学

```
问题：400+ 种已亡佚古籍在水经注中保存了什么？
方法：提取全部「《书名》曰」句式 → 建立引书-引文数据库
产出：
  - 引书频次排行（预期前五：《汉书》《说文》《山海经》《博物志》《华阳国志》）
  - 每种亡佚书的「水经注存世引文量」——文献学有实值
  - 引书按地域分布（某些书只在南方水道被引——暗示郦道元的南方文献来源）
```

#### （3）传说与地理的分层

```
问题：郦道元记述中有多少是神话传说 vs 地理实录？
方法：标注含「相传」「昔」「黄帝」「禹」「神」「龙」「怪」等词的段落
产出：每条水道的「传说密度」——干流 vs 支流、北方 vs 南方的分野
发现预期：源头段（上游）传说密度高于中下游——「河出昆仑」的神话地理学
```

#### （4）水文生态记录

```
问题：北魏时期河流的水文特征（流量、季节、鱼类、渡口密度）？
方法：提取含「冬」「夏」「竭」「溢」「鱼」「桥」「渡」的句子
产出：气候史和水文史的定量证据——这是自然科学引用水经注的主要场景
```

#### （5）与方舆经纬的互文网络 ⭐

```
问题：顾祖禹（明末）如何使用郦道元（北魏）的材料？
数据基础：方舆经纬已实现水经注被引 924 次（全书引书之冠）
方法：
  1. 在读史方舆纪要全文中定位全部 924 处《水经注》引用
  2. 对比两书同一地名的描述差异（1,100 年的地理变迁）
  3. 分析顾祖禹引用水经注的选择偏好（引了什么·没引什么）
产出：
  - 互文对照地图：同一地点，两个时代的记述并排
  - 引用选择分析：顾祖禹倾向引用水经注的哪些类型的内容？
  - 这本身就是一篇可投的论文：《从方舆纪要看明人对水经注的接受》
```

### 4.3 论文预期框架

```
《水经注》的空间网络与引书考古——基于全文本计量的数字人文研究

摘要：
  对郦道元《水经注》四十卷进行全书文本计量与水道网络分析。
  (1) 1,252 条水道的注意力分布呈极度长尾——河水五卷独占 1/8；
  (2) 南北方记述质量不对称（北魏人的南方知识来自文献而非实地）；
  (3) 400+ 种亡佚古籍的引文网络——水经注作为「古籍保存器」的定量证据；
  (4) 与《读史方舆纪要》的互文分析——1,100 年地理知识的传承与断裂。

关键词：水经注 · 水道网络 · 引书考古 · 文本计量 · 数字人文 · 互文分析
```

## 五、与方舆经纬的架构共享

### 5.1 共享层

```
GitHub 仓库结构（两个选择）：

方案 A：独立仓库（推荐）
  V-T-V/fangyu-jingwei     → 方舆经纬（读史方舆纪要）
  V-T-V/shuidao-jingwei    → 水道经纬（水经注）

  优点：各自独立部署、CI 不互相干扰
  缺点：工具代码复制

方案 B：monorepo
  V-T-V/jingwei-platform
    /fangyu/    → 方舆经纬
    /shuidao/   → 水道经纬
    /shared/    → 公共工具
  优点：一套 lint/CI/验证基建
  缺点：部署复杂化；GitHub Pages 需子路径

推荐 A：独立仓库。理由：方舆经纬已稳定运行，不宜为下一个项目动地基。
水道经纬复制 tools/ 与 vendor/ 起步，经验回流时选择性合并。
```

## 八、核心卖点总结

| # | 体验/发现 | 方舆经纬没有的 |
|---|---|---|
| 1 | **循水而读**：沿河阅读，地图跟随文本移动 | 方舆是点状跳转，水道是线状沉浸 |
| 2 | **水系树**：可视化 1,252 条水的干支拓扑 | 方舆只有行政层级，水道有自然网络 |
| 3 | **古今改道对照**：北魏黄河 vs 现代黄河双线叠加 | 方舆只做行政古今对照 |
| 4 | **引书考古**：400+ 亡佚古籍的引文溯源 | 方舆引书仅 20 种，水经注是古籍保存器 |
| 5 | **互文网络**：与方舆经纬 924 处引用的跨书互查 | 首个跨项目数字人文联动 |
| 6 | **传说密度地图**：神话地理学——源头多传说、下游多实录 | 全新维度 |

## 九、风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 北魏地名坐标考证量大 | 高 | 分优先级：前 50 条水道占注文字数 80%——先做核心 |
| 经注分离准确率 | 中 | 方法 A/B/C 三路交叉；学界有标度参考 |
| 河流折线精度 | 中 | 首版直线段（可接受）；后续接 Natural Earth 真实河线做校正 |
| 方舆经纬坐标复用率低 | 中 | 北魏县名与明县名重合度约 30-40%——需新建坐标层 |
| 文本源质量（缺字/错字） | 低 | 国学导航本质量可控；校勘不属本项目范围 |
